# MDK 0.17.0 update

**Goal:** Update Codr's embedded and standalone connector source to the exact
MDK v0.17.0 release, preserving Codr's extensions and worker supervision.

**Source:** v0.17.0 peels to `4df811aea99269b437a6023be9446a5141e93cbe`.
The old pin is MDK 0.14.0. Account schema migrations are one-way; this source
update does not authorize deployment or opening real account storage.

1. Add a failing provenance regression for version, revision, storage cohort and
   every MDK Git dependency. Keep historical 0.9/0.14 fixtures unchanged.
2. Rebase `patches/mdk-codr.patch` on the release. Preserve founding-admin and
   opt-in media recovery controls, atomic group creation and host shutdown.
3. Refresh the existing vendored crates from that patched source and rewrite
   only workspace dependency locations. Preserve release dependency/security pins.
4. Update `connector.toml`, lockfile and current docs/changelog. Change the
   storage cohort to `mdk-0.17` so automatic 0.14 upgrades fail closed. Do not
   widen the legacy external-to-combined handover's 0.14-only gate.
5. Verify patch application against clean release source, patched connector
   tests, host Rust/Python tests, format and strict Clippy. Use synthetic homes
   only and central build-storage adapters. Get two independent read-only
   reviews; fix demonstrated findings and verify again.

No running-service changes, account migration, version bump, commit, push or
release in this task.

## Verification record

- All four upstream 0.17.0 cohort tags resolve to the pinned release commit.
- The source preparer applies the regenerated patch to a clean release checkout;
  all 383 vendored crate files match that result byte-for-byte, excluding local
  agent instructions. Founding-admin support is now upstream.
- Host verification passed 512 Rust tests (eight ignored live tests) and 176
  Python tests. Strict host and connector all-feature Clippy, format checks,
  standalone binary checks and the optimized native release check passed.
- Protocol tests passed 33 cases; media/timeline tests passed six cases.
- The initial broad connector run passed 202 tests but failed 38 socket fixtures
  under the long temporary root. A focused reproduction returned
  `SocketPathTooLong`. The unchanged source then passed 282 connector/protocol
  tests (one ignored) from a short-named scratch checkout through the same storage
  adapter. No socket limit or adapter configuration was changed. The retry used
  the upstream CI's debug-info-off profiles.
- Both independent read-only reviewers reported no remaining demonstrated
  findings after adding the required `llvm-tools-preview` component.
- Real 0.14-to-0.17 migration, phone interoperability, Intel macOS and release
  packaging remain separate validation gates. The installed runtime is unchanged.
