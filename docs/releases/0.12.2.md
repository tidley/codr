# codr 0.12.2

Release candidate, not yet published. Prepared on merged `master` source
`c32d24f4e0d424d3c4f40f2510e00eb7a2d67cca` (PR #29), with coordinated 0.12.2
package, plugin and root lockfile metadata. Fresh qualification of the final
0.12.2 source is required on all four platforms. No completed release packaging,
published release, installed update, account migration or verified mirror is claimed.

## Release correction

- Immutable `v0.12.0` remains at `ff0ead28fbdfe9245de59bc719a25e2233d582a6`.
  Its [tag run 44176709277](https://github.com/tidley/codr/actions/runs/44176709277)
  compiled Linux x86_64, then exited 139 at the `--version` startup smoke.
  Publication was skipped. [PR #27](https://github.com/tidley/codr/pull/27)
  suppressed the musl GCC-injected runtime interpreter for Rust's self-relocating
  x86_64 static PIE, retaining PIE, musl linkage and version/help/static-loader smokes.
- Immutable `v0.12.1` remains at `29a44106ebbd022cca952d558557258aad251fc1`.
  Its [tag run 45587845551](https://github.com/tidley/codr/actions/runs/45587845551)
  passed Linux x86_64 startup smokes and connector protocol tests, plus complete
  Linux ARM64 and both macOS package lanes. The x86_64 lane failed later in
  `just fast-ci`: upstream policy archive fixtures could not execute missing
  `zstd`. That lane's artifact upload and release publication were skipped.
- [PR #29](https://github.com/tidley/codr/pull/29), now merged on `master`, adds
  `zstd` to the existing Linux packaging container prerequisites. It does not
  weaken or skip upstream policy or other gates. Its
  [Linux/macOS host CI](https://github.com/tidley/codr/actions/runs/45603879049)
  passed; that is not four-platform package qualification.
- Recovery uses the approved new version **0.12.2**, not replacement of either
  old tag. The existing tag workflow rebuilds all four platforms; there is no
  stable artifact-promotion path. Prior artifacts retain their original source
  and version and cannot be relabelled or mixed into a 0.12.2 release.

## Retained changes since 0.11.2

- Configured OpenCode V2 phone prompts use the authenticated local API with a
  persisted message ID and native acceptance receipt. Uncertain sends reconcile
  by ID without another POST or fallback terminal typing. Acceptance is not task
  completion. Codex, Claude Code and legacy OpenCode retain terminal delivery.
- Wide Markdown tables display as labelled rows on phones, retaining formatting
  and links without changing native histories or delivery receipts.
- Serial controls such as `/recent /unmute` validate together and run left-to-right
  with durable receipts. Launches, updates and permission answers stay separate.
- An exited or panicked embedded messaging worker stops the combined service so
  the existing supervisor can recover it; durable bridge state is preserved.
- Linux builds select `musl-gcc` to avoid mixing glibc's static math library with
  Rust's musl runtime. PR #27's interpreter suppression applies to x86_64 only.
- Unfinished Teem progress feature [#26](https://github.com/tidley/codr/issues/26)
  is excluded. This metadata preparation changes no runtime source, dependencies,
  build scripts/workflows, release channels, artifact contracts or connector pin/patch.

## MDK 0.17.0 storage boundary

Retain MDK 0.17.0 at `4df811aea99269b437a6023be9446a5141e93cbe`, the
`mdk-0.17` storage cohort, SQLCipher and security/storage backports.
`connector.toml` remains upstream **0.17.0**, not Codr's release version.
Codr's media-reference and graceful-shutdown extensions and upstream licence/source
notices remain intact.

Normal updates refuse the released MDK 0.14-to-0.17 boundary. Keep running
installations unchanged: migration needs separate owner approval and a private,
verified stopped backup of the complete account home and credentials. Downgrade
after opening the new schema is unsupported; never restore old MLS state over
newer traffic. The supported fresh-account bootstrap remains 0.9.0 followed by
the documented compatible handover, not automatic migration to this candidate.
See the [combined-runtime guide](../COMBINED.md#mdk-017-storage-boundary).

## Verification and publication limits

The [release handoff](0.12.2-readiness.md) separates historical evidence from
pending exact-candidate checks, two independent reviews and fresh Linux x86_64,
Linux ARM64, macOS Intel and macOS Apple Silicon packages. Preserve startup,
connector protocol/provenance, upstream policy, signing and checksum gates.
GitHub publication must precede ngit/Blossom mirroring of the exact bytes with
human Amber signing approval and independent download verification. Publication
does not authorize installation, live probes, service restarts or account migration.
