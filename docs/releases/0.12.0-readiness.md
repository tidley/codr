The narrower read-only GitHub job-log endpoints supplied the failure evidence:

- `repos/tidley/codr/actions/jobs/133603675122/logs`: final link used `cc` with
  Rust's `x86_64-unknown-linux-musl` CRT and glibc's
  `/usr/lib/x86_64-linux-gnu/libm-2.35.a(s_cbrt.o)`. It failed with undefined
  `__frexp` and `__ldexp`; Cargo exited 101.
- `repos/tidley/codr/actions/jobs/133603674891/logs`: the same `cc`/musl mismatch
  selected `/usr/lib/gcc/aarch64-linux-gnu/11/../../../aarch64-linux-gnu/libm.a(s_cbrt.o)`
  and failed with the same two undefined symbols; Cargo exited 101.

MDK Markdown adds `-lm` to the final link. Selecting the host GNU linker driver
mixed glibc's math archive with musl. Both Linux jobs already install
`musl-tools`; explicitly selecting its native `musl-gcc` wrapper for each musl
target is the minimal repair. Target-specific Cargo environment variables leave
Darwin and the standalone GNU compatibility connector unchanged. Static-loader,
version/help, connector protocol/provenance and upstream policy gates remain.
