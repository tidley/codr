# codr 0.11.0

This release follows 0.10.0. It retains one executable for the bridge and MDK
messaging runtime, the existing MDK 0.14 storage cohort, and explicit update and
service-handover confirmations. It does not authorize storage migration.

## Claude replies during background tasks

- Forward completed Claude `end_turn` replies while a background task keeps
  herdr reporting the session as working. Unfinished replies are not finals.
- Treat Claude's system-sourced task notifications as notifications, not local
  human prompts. They do not mute every chat or create a new conversation turn.
- Retain an already completed response when Claude starts another response in
  the same turn. Incomplete continuations still supersede incomplete responses.
- Keep the existing progress bubble until the session settles. Repeated working
  polls must not create an unfinished replacement after a completed reply.
  Status/checklist refresh and durable final replies remain separate.

These changes integrate Juraj Bednar's [PR #20](https://github.com/tidley/codr/pull/20)
with a progress-lifecycle correction and regression coverage.

## Clear update status

When no newer version is available, `/update` reports:

> No new version available. Currently running codr 0.11.0.

This is a version check, not an installation receipt. It does not install or
convert services. An available update still requires owner confirmation.

## Upgrade and verification limits

Existing combined 0.10 installations use `/update`, then `/update confirm`.
Existing 0.9 installations retain the separate two-confirmation executable
update and cold-backup service handover described in [COMBINED.md](../COMBINED.md).
Fresh identities still use the supported 0.9.0 setup before handover.

The live phone-driven handover remains unverified end-to-end. Local tests and
platform CI do not establish that round trip. Foreman, worker-sharing filters
and encryption experiments are outside this release. Existing account data,
history, accepted deliveries and native coding sessions must remain intact.
