## Required qualification and coordinator actions

1. Freeze and identify the exact metadata/docs snapshot. The supervisor runs,
   from the repository root, `cargo test --locked --tests`,
   `cargo fmt --all --check`,
   `cargo clippy --locked --all-targets -- -D warnings`, and
   `python3 -m unittest discover -s tests -p 'test_*.py' -v` using the central
   fastbuild adapters and the pinned Odin prerequisite. These checks and two
   independent read-only reviews are pending for this candidate. One review covers
   correctness/contracts/security/compatibility; the other tests/regressions/
   complexity/scope. Execution success is not review approval. Existing version
   tests derive the release version, so no test edits or dependency update are needed.
2. After qualification, the coordinator handles authorized scoped source
   integration/publication and records the final release commit. Reinspect remote
   refs, releases, in-flight runs and retained artifacts first. Do not dispatch a
   duplicate build, change old tags or treat this uncommitted worker diff as a tag.
3. The existing workflow has **no stable artifact-promotion job**. A normal master
   push runs host checks; a version tag rebuilds and publishes after the package
   matrix passes. A dispatch builds artifacts but does not publish stable releases.
   Because 0.12.1 changes compiled version metadata and contains the #27 repair,
   fresh builds for its exact source are required, not old 0.12.0 assets. The
   authorized coordinator must explain this required tag-triggered rebuild before
   triggering it, then use that run rather than a duplicate preparatory dispatch.
4. Require Linux x86_64/ARM64 and macOS Intel/Apple Silicon package lanes, version/
   help/static-loader smokes, connector protocol/provenance, upstream policy and
   macOS signing checks. Preserve MDK/SQLCipher/security pins and all existing gates.
   Record exact source, version, build inputs, signing, results and SHA-256 checksums
   of downloaded final archives and checksum files. Prior host passes and local
   musl experiments do not replace any platform gate.
5. Publish GitHub first using `docs/releases/0.12.1.md`; retain identical contributor
   credits. Mirror approved refs and existing CI evidence, then the exact unchanged
   release assets/checksum files through the supported [ngit/Blossom procedure](../MIRRORING.md).
   Human Amber approval (`devbox-amber`) and independent mirrored-download SHA-256
   verification remain required. Report source, CI, release and mirror states
   separately; pending signatures/uploads are not publication success.
6. Keep installation/runtime validation and MDK storage migration separate. No
   account access, live agents/probes, service restart, deployment or migration
   is authorized for this worker. Normal updates must refuse MDK 0.14-to-0.17;
   any later migration needs separate approval and a verified private cold backup.

This worker does not run supervisor-owned checks, delegate reviews, commit, push,
merge, create a PR/tag, dispatch CI, publish, install or change runtime permissions.
