# codr 0.12.1

Release candidate, not yet published. Prepared from merged `master` source
`31adb78d638918921eda16620615bb3199754216` (PR #27), with coordinated 0.12.1
package, plugin and root lockfile metadata. Fresh qualification of the final
0.12.1 source is pending on all four supported platforms. No installed update,
completed packaging, account migration or verified mirror is claimed.

## Linux x86_64 startup repair

- The immutable `v0.12.0` tag remains at
  `ff0ead28fbdfe9245de59bc719a25e2233d582a6`. Its
  [tag build](https://github.com/tidley/codr/actions/runs/44176709277) compiled
  Linux x86_64 successfully, then exited 139 at the `--version` startup smoke.
  Release publication was skipped; no GitHub 0.12.0 release was published.
- PR #27 adds `-C link-arg=-Wl,--no-dynamic-linker` for x86_64 musl release and
  preview builds. The native musl GCC specs injected an interpreter into Rust's
  self-relocating static PIE. Suppressing that interpreter fixes the demonstrated
  pre-main crash mechanism while retaining PIE, musl linkage and startup smokes.
- Dependency-free and full-application local red/green experiments are retained
  in the [historical evidence](0.12.0-readiness.md). Those 0.12.0-labelled
  diagnostic executables are not approved 0.12.1 release packages. Neither the
  old tag nor its successful ARM64/Mac artifacts may be relabelled.

## Retained changes since 0.11.2

- Configured OpenCode V2 phone prompts use the authenticated local API with a
  persisted message ID and native acceptance receipt. Uncertain sends reconcile
  by ID without another POST or fallback terminal typing. Acceptance is not task
  completion. Codex, Claude Code and legacy OpenCode retain terminal delivery.
- Wide Markdown tables display as labelled rows on phones, retaining inline
  formatting and links without changing native histories or delivery receipts.
- Serial controls such as `/recent /unmute` validate together and run left-to-right
  with durable receipts. Launches, updates and permission answers stay separate.
- An exited or panicked embedded messaging worker stops the combined service so
  the existing supervisor can recover it; durable bridge state is preserved.
- Linux builds explicitly select `musl-gcc` to avoid mixing glibc's static math
  library with Rust's musl runtime. ARM64 and Darwin flags are unchanged by #27.
- Unfinished Teem progress feature [#26](https://github.com/tidley/codr/issues/26)
  is excluded. This preparation changes no runtime source, dependency, workflow,
  release channel or artifact contract.

## MDK 0.17.0 storage boundary

Retain MDK 0.17.0 at `4df811aea99269b437a6023be9446a5141e93cbe`, the
`mdk-0.17` storage cohort, SQLCipher and security/storage backports. The
`connector.toml` version is the upstream **0.17.0**, not Codr's release version;
it must not be bumped to 0.12.1. Codr's media-reference and graceful-shutdown
extensions and upstream licence/source notices remain intact.

Normal updates refuse the released MDK 0.14-to-0.17 boundary. Keep running
installations unchanged: migration needs separate owner approval and a private,
verified stopped backup of the complete account home and credentials. Downgrade
after opening the new schema is unsupported; never restore old MLS state over
newer traffic. The supported fresh-account bootstrap remains 0.9.0 followed by
the documented compatible handover, not automatic migration to this candidate.
See the [combined-runtime guide](../COMBINED.md#mdk-017-storage-boundary).

## Verification and publication limits

The [release handoff](0.12.1-readiness.md) separates prior-source evidence from
pending exact-candidate tests, two independent reviews and fresh Linux x86_64,
Linux ARM64, macOS Intel and macOS Apple Silicon packages. The existing tag
workflow rebuilds for the new version and publishes only after its gates pass;
there is no stable artifact-promotion job. Preserve connector protocol/provenance,
upstream policy, signing and checksum checks. GitHub publication must precede
ngit/Blossom mirroring of the exact bytes with human Amber signing approval and
independent download verification. Publication does not authorize installation,
live probes, service restarts or account access/migration.
