# codr 0.12.0

Release candidate. Not yet tagged or published. Cross-platform package results
must qualify the exact source commit before publication.

## Native OpenCode prompt delivery

- With a configured OpenCode V2 service, phone prompts go directly to their
  mapped native session through its authenticated loopback API.
- Codr saves a unique native message ID before sending. The returned durable
  inbox receipt confirms acceptance, not execution or successful completion.
- Lost acknowledgements are reconciled by ID from saved messages or the inbox,
  including after restart. Codr never repeats an uncertain POST or switches to
  terminal typing. Recovered acceptance restores queue and forwarding state.
- Codex, Claude Code and legacy OpenCode without a configured V2 service retain
  their existing terminal delivery. No native agent session is replaced.
- Prepared attachments retain the existing local-file-reference path. This does
  not add quoted-message text or attachment resolution.

## MDK 0.17.0 and the storage boundary

- Embedded and standalone connector sources move from MDK 0.14.0 to the exact
  0.17.0 release, commit `4df811aea99269b437a6023be9446a5141e93cbe`.
- Retain Codr's media-reference and graceful-shutdown extensions. Founding-admin
  controls now come from upstream. Preserve upstream licence/source notices.
- The storage cohort changes from `mdk-0.14` to `mdk-0.17`. Normal updates refuse
  that boundary; they must not silently migrate an existing account.
- An owner-approved migration requires a stopped, verified backup. Opening the
  newer account schema is one-way: downgrade is unsupported. Never restore old
  MLS state over an account that has subsequently processed newer traffic.
- The runtime includes upstream reconnect, queued-send, history-recovery,
  attachment-scheduling, account/group read and security improvements. New MDK UI
  features do not automatically become Codr commands.
- Source builds require the pinned Odin compiler and Rust LLVM tools; see the
  [combined runtime guide](../COMBINED.md).

## Other changes since 0.11.2

- Wide phone tables become labelled rows while preserving links and formatting.
- Serial controls such as `/recent /unmute` are validated together and dispatched
  left-to-right. Durable command receipts prevent repeated completed controls.
- If the embedded messaging worker exits or panics, Codr stops so its service
  supervisor can restart it instead of leaving phone messaging silently offline.

## Verification and release gates

Local development checks and the approved local account migration are not
cross-platform release certification. Required verification includes host tests,
two independent reviews of the combined diff, live attachment and busy-session
API checks, and Linux x86_64/ARM64 plus macOS Intel/Apple silicon package lanes.
Do not relabel the earlier installed 0.11.2-labelled development executable or its
artefacts as a 0.12.0 build. Keep original CI run links and verify package checksums.

The isolated live API probe passed prepared text-file and PNG references: the
agent returned the file's unique token and identified the image's square color.
A follow-up sent while both its session and shell tool were running was accepted
and included in the final reply. Both saved message IDs appeared exactly once.
This used the production OpenCode service and Codr's native transport helper, not
a fresh phone-network attachment download. Existing production chats were not used
as probe targets. The opt-in test in `tests/native_prompt.rs` stays ignored unless
an explicit scratch-session identity and validation payload are supplied.
