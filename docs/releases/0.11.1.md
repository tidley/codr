# codr 0.11.1

This patch follows 0.11.0. It keeps the same MDK 0.14 source pin, dependencies,
control protocol, bridge state version, and storage cohort. It does not need or
authorise an account migration.

## Phone answers resume the current question turn

A confirmed phone answer allows future replies from the current unfinished
question turn to reach the phone even if the turn was previously muted. Old
replies and other chats stay suppressed, and explicit `/sync off` remains in
effect. Failed, stale, or uncertain answers do not resume the turn. `/last`
remains a read-only replay.

## Nested project folders

Guided `/new` accepts nested relative paths such as `apps/new-project`.
Use `ls Apps/Library/` to list an existing subfolder or `ls Apps/Library/part`
to filter its entries. Directories remain selectable; regular files are shown
separately for reference. Listing never creates folders. Existing root, symlink,
traversal, and confirmation checks remain in force.

## Ordinary follow-ups after completed questions

After Codr observes that an agent is no longer blocked, ordinary text such as
`Retry ngit` starts a new prompt. It no longer becomes an answer to an old custom
question, including after a bridge restart.

Numbers, option labels, question codes, and `/answer TEXT` remain explicit
answer attempts. A stale answer cannot become a new prompt. A question that stops
waiting during a reply still fails closed. Duplicate delivery remains suppressed.

## Visible progress after questions

OpenCode question cards start with the question and its choices, without an
internal decision heading, request code, repeated title, or routine instructions.
Changed-question codes and unsupported-dialog notices remain only when needed
to answer safely. Request validation is unchanged.

When an agent resumes work after waiting for input, Codr starts a fresh editable
working/checklist message at the bottom of the conversation. It clears the old
progress to `Task continued below.` only after the new message is confirmed.
The old message is not deleted. This edit is best effort, without uncertain
retries. Questions, answers, and final replies remain intact. Follow-ups while
already working still reuse the current progress message. This applies when
editable responses are enabled.

## Cleaner session labels and chat titles

- Mobile-created agents keep a unique startup name until Herdr confirms the
  start. Codr then clears the temporary `codr-…` label through Herdr's rename API.
  A failed cleanup leaves the agent running and produces a warning. It does not
  repeat the launch or send a prompt.
- Fresh-session chats add `opencode`, `claude`, or `codex` only while another live
  project chat has the same tab/workspace title in that workspace. Unique titles
  stay short, such as `marmot (bits)`.
- Creation, automatic metadata updates, and explicit renaming use the same rule.
  Existing manual-title locks and uncertain-update guards remain active.
- The current account-creation helper uses **👾** for both public profile fields.
  Existing accounts, custom profiles, keys, chats, and accepted work stay intact.

## Setup and upgrade limits

The supported fresh-account path still starts with 0.9.0 setup before the
existing handover. That older setup keeps its original profile default. This
release does not rename it automatically or add a combined-account setup wizard.

Existing combined installations retain `/update`, then `/update confirm`, after
publication and verified release mirroring. Existing 0.9 installations retain
the separate executable-update and cold-backup handover confirmations. See the
[combined runtime guide](../COMBINED.md). The live phone-driven handover remains
unverified end-to-end.

Foreman orchestration, worker-sharing filters, Mac recovery changes, and the
encryption experiments are outside this patch release.

## Verification and provenance

The behavioural fixes passed local tests and two independent reviews before
local deployment. The current deployed candidate reports 0.11.1 and includes the
retained progress message and simplified question display. Its source is the
published 0.11.0 base plus a saved local patch, not a published 0.11.1 tag.
Account identity, 30 chat mappings, message receipts, and native sessions survived
the approved Codr-only restart. Herdr and OpenCode were not restarted by the
deployment.

That deployment does not prove the whole phone workflow or platform release readiness.
Version-specific CI, platform packages, signing, and download verification remain
required. Do not relabel the earlier local executable or 0.11.0 CI artifacts as
0.11.1 builds. See the [readiness record](0.11.1-readiness.md) for source-specific
verification and publication gates.
